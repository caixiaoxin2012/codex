# SCL AI Analyzer 版本管理规则

从 V0.9.5 起，所有较大的功能改动必须使用独立 Git 版本号区分，禁止把多个大功能长期堆叠在同一个版本号中。

## 版本格式

采用语义化版本：`MAJOR.MINOR.PATCH`。

- `PATCH`：新增一个可独立验收的功能模块、较明显的功能增强或兼容性改进。例如 `0.9.5 -> 0.9.6`。
- `MINOR`：形成一个新的产品阶段、架构层或一组较大的能力集合。例如 `0.9.x -> 0.10.0`。
- `MAJOR`：达到稳定正式产品或发生不兼容的大架构升级。例如 `0.x -> 1.0.0`。

## 每次大功能改动必须同步

1. 更新 `pyproject.toml` 中的版本号。
2. 使用包含版本号和功能名称的 Git commit message。
3. 在报告/README/CHANGELOG 中记录该版本新增能力和已知限制。
4. 新功能必须有独立测试文件或补充对应回归测试。
5. 不把尚未验证的能力描述为已经通过真实 TIA 工程验证。

## 当前基线

- `V0.9.3`：双向定位 + 工程知识图谱。
- `V0.9.4`：标准功能库解析 + 状态机动作与设备关联。
- `V0.9.5`：状态机动作、设备、完成条件、下一状态、报警/联锁因果链。

下一项大的功能开发从 `V0.9.6` 开始，并保持一项主要能力对应一个清晰版本。
