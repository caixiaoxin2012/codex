# SCL AI Analyzer V1.0 产品规格

## 产品目标

将 TIA Portal V16–V21 导出的项目文件投入工具后，在 10 分钟内自动生成一套可复核、可定位、可导出的 PLC 工程分析框架。

## 输入范围

- TIA Portal / Openness 导出的 XML
- SCL 源文件
- UDT / DB / AWL 文本导出
- 项目库导出的标准功能块资料
- 多文件、多目录项目结构

> V1.0 不直接修改 `.zap16` 工程，仅解析导出内容。

## 核心输出

1. 项目树状结构
   - OB → FB/FC → 实例 → DB/UDT
   - 识别跨文件调用关系
   - 标记未解析调用、缺失定义和孤立块

2. FB / FC 标准功能库解析
   - 接口变量
   - 输入、输出、InOut、Static、Temp
   - 多重实例
   - 调用点和参数连接
   - 来源文件和行号
   - 功能说明模板

3. 双向定位
   - 报告条目可回到源文件、块名和行号
   - 源代码中的调用、状态和报警可映射到报告章节
   - 每个 AI 结论必须保留来源证据

4. 状态机识别
   - 识别 CASE 状态机
   - 提取状态编号、状态名称和转移条件
   - 检查未到达状态、无出口状态和重复状态
   - 生成状态转移表

5. 报警分析与颜色分级
   - 严重：红色
   - 警告：橙色
   - 建议：黄色
   - 信息：蓝色
   - 每条报警显示来源块、变量、条件和行号
   - 涉及安全联锁时必须标记“人工复核”

6. Word 报告导出
   - 项目摘要
   - 项目树
   - FB/FC/OB/DB/UDT 索引
   - 调用关系
   - 状态机
   - 报警和风险
   - 变量表
   - 代码证据附件

## 十分钟目标流程

```text
选择项目目录
→ 自动识别 TIA 版本
→ 扫描 FB / FC / OB / DB / UDT
→ 构建调用图和实例关系
→ 识别状态机和报警
→ 生成树状结构与风险分级
→ 导出 Word 报告
```

## 架构原则

- 结构解析由规则引擎完成
- 工艺解释和文档表述由 AI 完成
- 所有结论必须可追溯到源文件和行号
- AI 输出不得覆盖原始代码事实
- 无法确认的内容必须标记为“待人工确认”
- V16–V21 统一转换为内部 AST 模型

## V1.0 验收标准

- 真实项目在 10 分钟内生成初步报告
- FB、FC、OB、DB、UDT 识别率目标不低于 90%
- 调用关系可回溯到来源文件和行号
- 至少支持一种典型 CASE 状态机识别
- 报警按颜色和等级输出
- Word 报告可正常打开并用于项目交接
- 关键结论具备代码证据和人工复核标识
